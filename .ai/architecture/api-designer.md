# API Designer

## Objective

Create predictable component APIs.

## Rules

Props must:

- Be intuitive
- Be discoverable
- Follow existing naming patterns

## Naming

Good:

isOpen
isDisabled
isLoading

Bad:

opened
activeState
loadingStateFlag

## Variants

Prefer:

variant="primary"
variant="secondary"

Avoid:

primary={true}

## Validation

Would another developer understand this API in 10 seconds?
